# FileCrypt v2 容器设计草案

**状态：设计草案，尚未冻结，尚未实现。** 本文确定首版的逻辑结构和读取规则；具体字段偏移、宽度、编号及密码学参数仍须补齐规范与测试向量，不能据此宣称已有可互操作的 v2 文件。

产品范围见 [v2 计划](README.md)，密钥与认证规则见 [密码学设计](CRYPTOGRAPHY.md)，验收要求见 [验证计划](VALIDATION.md)。已发布 v1 格式见 [v1 文件格式](../v1/FILE_FORMAT.md)。

## 1. 版本与交付形态

首版继续使用一个 `.fcry` 文件保存单文件或目录归档。文件仅共用六字节识别前缀：

| 字段 | 已确定编码 |
| --- | --- |
| Magic | 四字节 ASCII `FCRY` |
| Version | 两字节小端无符号整数，v2 为 `2` |

六字节之后按版本独立解释，不沿用 v1 的 32 字节 Header、Metadata 对齐、Registry 编号、Tag 偏移或目录 Entry 编码。识别字段用于选择处理流程，其值仍须纳入相应版本的认证上下文。

未知版本明确拒绝。v1 或 v2 的解析、资源检查或认证失败后，均不尝试另一版本。当前程序仍只实现 v1；新增文档不改变现有创建文件的默认版本。

## 2. 逻辑布局

```text
FCRY + Version 2
  → 公共头：不可变数据描述、单密码密钥包装区、头认证
  → 加密清单记录：单文件信息或完整目录清单
  → 有序数据记录：各自认证，可独立压缩
  → 认证结束记录
  → 恰好到达 EOF
```

上图表示逻辑次序，不是已冻结的字节布局。清单可以由多个有序、受限的记录承载，不要求目录清单能装进一个数据块；首版仍要求完整清单能在配置的内存上限内处理。

首版采用固定布局、小端整数及明确长度的专用二进制编码；各套件的字段宽度与排列分别固定，不直接保存本机结构体。名称使用带长度的 UTF-8 字节。首版不设置通用 TLV 或可跳过扩展区，拒绝未知类型、未知标志、非零保留字段和非规范编码。后续扩展必须明确读取器支持要求，不能依赖旧程序忽略未理解的内容。

完整清单位于所有数据记录之前。首个认证清单片段声明清单总字节数、条目数与片段数量；读取器按序认证全部片段，核对声明并精确消费编码后，才能将清单视为完整。清单自身的完成判断不依赖文件末尾的 END，供 `list` 在不读取数据记录时使用；整个文件的完整性仍需 END 与精确 EOF。

| 部分 | 作用与约束 |
| --- | --- |
| 不可变数据描述 | 识别数据套件、容器身份、记录组织及解析所需的上限信息；数据记录认证绑定其确定编码或摘要 |
| 密钥包装区 | 保存单密码入口所需的 Salt、KDF 参数和包裹的数据密钥；绑定相应数据描述 |
| 头认证 | 覆盖规范规定的完整头部信息，防止字段或包装信息被移植、删改；确切编码与覆盖范围在密码学规范中冻结 |
| 加密清单 | 描述原始名称、单文件或目录类型、树结构、每个文件的逻辑长度及数据对应关系 |
| 数据记录 | 保存小文件合包或大文件分块对应的密文、认证标签和必要记录信息；文件归属、包内区间与文件内位置也受认证 |
| 结束记录 | 认证记录数量、编码载荷总量及恢复数据总量，确认完整输入已经结束 |

公共头只暴露识别、解锁和有界读取所需的信息。文件名称、单文件或目录类型、树结构及文件到数据块的映射放在加密内容中。外部记录边界与长度仍可能暴露数据特征，v2 不承诺隐藏总大小或全部访问模式。

不可变数据描述与密钥包装区在设计上分离，不表示首版支持原位改头、快速重包或多个解锁入口。

## 3. 记录与完整性

记录的逻辑身份至少包括所属容器、全局顺序、记录类型与长度；数据记录还必须绑定其中各文件片段的身份与顺序。文件 ID、文件内偏移、包内区间和逻辑长度放入加密内容，不能通过公共记录头暴露文件映射。记录内采用明确区分的映射信息与数据区，映射在记录认证后解析，再按该记录的编码方式处理数据区；字段宽度与排列另由字节级规范固定。外部长度在认证前不可信，必须先按运行预算检查，不能直接用于任意分配或定位。

读取器必须同时检查：

1. 记录属于当前容器，顺序符合状态机，没有缺失、重复、错序或非法类型转换。
2. 每个记录完整认证后才向解压器、清单解析器或恢复流程提供其明文。
3. 数据记录与清单声明的文件相对应；文件内顺序和累计长度准确，不存在未声明数据、非法引用或错误的跨文件拼接。
4. 结束记录的计数和长度与实际读取结果相符；结束记录之后恰好到 EOF。

空文件和空目录同样必须有有效清单及结束记录。没有数据记录不等于可以省略结束记录。正常 EOF、缺少结束记录、IO 失败和认证失败必须区别处理。

首版记录不可原地修改，不支持追加或断点续写。修改内容、重新压缩或失败后重新开始加密时，创建新的容器身份和数据密钥，不能沿用旧密钥与记录序号重新加密不同内容。

首版不另外保存全文件 SHA-256。整体完整性依赖逐记录认证、严格顺序、完整清单映射、认证 END 中的实际计数与长度以及精确 EOF；不能因省略整流摘要而省略这些检查，组合安全仍需独立审查。

### 小文件合包与大文件分块

2026-10-14 确认小文件合包，允许最后加入的完整小文件使包超过目标。当前草案将“4 MB”按 **4 MiB，即 4,194,304 字节**记录为暂定目标 `B`，按压缩前的文件内容字节累计，不含映射表、记录头或认证标签，也不按压缩结果决定何时封包。

为明确越界范围，草案暂将 `0 < 文件大小 < B` 定义为参与合包的小文件，`文件大小 >= B` 按大文件路径单独分块。该分类与 4 MiB 目标属于暂定策略，性能测量仍暂缓，不代表已经冻结最终参数。

1. 按清单中的文件顺序处理，小文件整份加入当前包，不为凑齐目标拆开文件。
2. 每加入一个文件后检查累计内容大小；达到或超过 `B` 就结束该包，下一个小文件进入新包。例如约 3.99 MiB 加入约 20 KiB 后超过 4 MiB，仍保留在同一包内。
3. 每次加入前累计大小小于 `B`，且加入的文件也小于 `B`，因此单包文件内容严格小于 `2B`，即 8 MiB。4 MiB 是封包目标，不能作为读取时的单包硬上限。
4. 遇到大文件时先结束尚未满的包；大文件只按自身顺序分块，尾块不与其他文件合包。大文件块大小另行确定，不从小文件包的软目标自动推导。
5. 空文件与空目录只由清单声明，不生成零字节数据片段；归档末尾仍有内容的未满包正常写出，不填充到目标。
6. 映射条目数、映射编码大小及整个记录的编码大小另设硬限制，加入文件前检查。大量极小文件可能在达到目标前触及这些限制，此时提前结束当前包；单个文件无法合法编码时明确拒绝，不能放宽限制、反复封空包或无界分配。

合包软目标约束写入策略；读取器不能仅因包未满目标而拒绝尾包或提前封闭的包。逻辑内容与记录编码的硬上限必须另由规范和运行预算明确，不能只把 4 MiB 目标传给分配器。

每个包的数据区是按顺序拼接的文件内容；开启压缩时，整个数据区作为一个压缩候选块。加密的映射信息记录文件 ID、文件内偏移、包内逻辑偏移和长度，包内偏移针对解压后的数据区。小文件对应一个完整片段，大文件由连续片段覆盖。读取器检查映射与清单一致、顺序一致、区间无重叠或间隙、每个文件恰好被完整覆盖；不得存在未声明数据或把包尾字节静默丢弃。

恢复前先认证整个记录，再解析受限映射、按需解压并校验全部区间，随后才能向暂存输出分发文件内容。包内文件共享该记录的认证与压缩边界；未来选择恢复其中一个文件，也需要读取并认证整个包。打包依据清单记录的大小；源文件增长、缩短或其他可检测变化必须失败，不能借此突破包或记录上限。

## 4. 独立压缩帧

首版保留不压缩和 Zstandard 两种行为。默认不压缩，沿用 v1 的 `compress` / `-z`、`no-compress` 及压缩等级 3，暂不调整这些默认值。启用压缩时，将每个小文件包或大文件块的数据区压缩成一个独立帧；压缩后大小没有严格小于原始数据区时，该记录保存未压缩数据。比较包含完整 Zstd 帧开销，编码方式及实际长度都受记录认证。关闭压缩时只允许未压缩数据记录，开启时允许两种编码混合出现。

压缩数据区必须恰好包含一个完整 Zstd 帧，不依赖前一块或外部字典；拒绝拼接帧、可跳过帧和未消费尾部字节。清单与映射信息不压缩。恢复顺序为“认证该记录 → 解析映射与编码 → 按需解压数据区 → 核对逻辑长度及映射”，解压前检查窗口和输出预算；未压缩数据同样检查长度与映射。

限制应分别覆盖单记录密文长度、解密后的编码长度、解压窗口、单块逻辑输出、累计逻辑输出和目录条目数量。必须明确区分：

- 编码载荷字节数：参与记录加密的完整内容长度；数据记录包含未压缩的映射及控制信息，以及数据区的实际编码（未压缩字节或完整 Zstd 帧），不能只计帧大小而漏计映射。
- 恢复数据字节数：用户文件内容的逻辑长度。
- 格式开销：记录头、标签、清单和结束记录等，不能与上述统计混用。

4 MiB 合包目标目前只作为暂定策略；大文件块大小、各项硬限制与最终参数依据另行补齐，资源与性能测量仍暂缓。协议允许的最大值与本机愿意处理的运行预算分别定义；映射开销不计入合包目标，但必须计入记录分配和密码套件用量。分块认证不意味着可以取消每密钥使用量或总文件预算。

独立压缩与分块认证不自动提供随机提取。首版仅承诺完整顺序恢复和验证。

## 5. 单文件与目录清单

清单使用专用二进制编码，父目录条目先于其子条目，条目序号作为文件或目录 ID。数据按清单中的文件顺序组织，忽略没有数据的目录和空文件；文件大小与结构声明足以确定应恢复的内容，数据记录中的映射必须逐项与之核对。精确字段宽度、根条目和清单分片编码仍需补齐。

单文件清单保存原始文件名及逻辑长度；名称作为一个路径组件处理，不保存可直接控制输出位置的绝对路径。首版恢复仍要求显式输出路径，v2 按该路径原样恢复，不使用归档名称覆盖目标或自动追加后缀；原名用于内容列表，用户可据此指定恢复名。v1 仍按原扩展名恢复规则执行。

目录清单保存普通文件、目录及其关系，包含空目录。首版继续拒绝源符号链接、Windows 重解析点与其他特殊对象，不同时引入链接恢复、ACL、原始所有者或权限继承。时间戳等额外元数据留作后续功能，不因存在字段空间就视为已支持。

可以复用 v1 已确立的安全语义，但必须使用 v2 自己的编码和引用模型：

- 名称必须是合法 UTF-8 单组件，拒绝路径穿越、分隔符、非法根关系和重复兄弟名称。
- 限制条目数、深度、名称长度、清单字节数和总文件数据量。
- 检查父子关系与文件数据映射，拒绝环、悬空引用及不一致的文件长度。
- 格式名称是否合法与目标文件系统是否能够恢复分别判断；目标平台的大小写冲突、保留名称及其他限制在恢复前检查，不自动改名。

首版目录恢复仍使用受限暂存目录；全部记录、目录结构和结束标记验证成功后，才发布最终目录。块已经认证不允许提前把部分目录作为完整恢复结果提交。

## 6. 命令所能证明的内容

| 操作 | v2 计划行为 |
| --- | --- |
| `info` | 无密码读取公共字段，明确未认证；加密字段不可得时不伪装成空名称、普通文件或无压缩 |
| `list` / `-l` | 两种写法完全等价；完整认证头和清单后展示名称、大小与目录关系，明确尚未完成全部载荷验证 |
| `verify` | 顺序认证全部记录、检查压缩与清单对应关系、结束记录及 EOF，不创建整份解密载荷临时文件 |
| `decrypt` | 与完整验证保持一致，恢复到输出事务；只在全部验证通过后提交 |
| `rekey` / `-r` | 按源格式处理并完整轮换数据密钥；验证新文件后另存或显式替换，具体规则见密码学设计 |

公共展示模型需要表达“尚未解锁/未知”，不能用当前 v1 展示字段的默认布尔值冒充认证结果。具体接口调整留到实现阶段。

解密过程仍需要暂存恢复文件，v2 的目标是减少为认证而暂存完整中间载荷的需要，不承诺恢复过程完全不写明文。任何磁盘删除都不等于安全擦除保证。
