# FileCrypt v2 验收方案

状态：待实施的验收计划，2026-10-14。本文列出需要建立的固定样本、向量、测试和测量，不宣称这些工作已经完成。v2 的布局、套件和数值上限尚未冻结，具体期望字节必须在对应规范确定后补齐。

产品范围见[开发范围](README.md)，记录组织见[文件格式草案](FILE_FORMAT.md)，密钥与认证约定见[密码学草案](CRYPTOGRAPHY.md)。任何协议规则变化都要同时更新对应向量及预期结果。

## 1. 验收原则

1. **固定历史样本与当前实现往返测试并存。** 同一版本代码自己生成、自己读取的成功结果不能单独证明历史兼容或编码正确。
2. **认证成功与内容合法分别检查。** 除了破坏密文，还要生成认证有效但压缩、清单或映射非法的测试文件。
3. **检查结果与副作用。** 失败时同时检查错误类别、非零退出状态、原文件和目标文件状态、临时输出清理及实际资源消耗。
4. **按每个版本验证资源策略。** 协议允许不代表本机允许执行；解锁前即检查未认证长度与 KDF 成本。
5. **平台结果逐项记录。** 本地 MinGW、Windows MSVC、Linux 原生与 QEMU 基线的结果分开记载，不能互相替代。

测试沿用现有 CTest 组织，保持单元、集成、素材测试的分层；完整大素材和压力测量不重复塞入每个命令组合。当前基线没有专用的固定历史 `.fcry` 样本集，需要新增，不能用现有目录素材 ZIP 代替。

## 2. 固定 v1 历史兼容样本

### 来源与可追溯性

以已经发布的 v1.1.0（`f073b29`）及确认可取得的更早版本生成样本。使用明确选定的旧可执行程序，不以开发分支重新构建出的最新写入器冒充历史生产者。

每份样本记录生成程序版本、提交、平台、可执行文件摘要、生成命令与选项、测试密码字节、原始输入摘要、加密文件摘要和预期元数据。测试密码与内容必须专用于公开夹具，不包含真实用户数据。密码边界样本记录 UTF-8 字节，而不只写可见字符串。

生成一次后保存固定密文及清单，不在每次测试时重新生成再当作历史样本。合法样本的变异文件或变异规则也应固定，记录修改位置与预期拒绝阶段。候选目录为 `tests/fixtures/v1/`；最终位置及分发方式在建立夹具时确定。

### 覆盖与预期

| 范围 | 最小覆盖 | 新版应满足的结果 |
| --- | --- | --- |
| 算法与载荷 | 两种已有算法，压缩开关，文件与目录 | `info` 保持已承诺字段；解密内容与摘要一致；`verify` 成功 |
| 空与边界 | 空文件、空目录、嵌套目录、零长度文件、旧实现处理块边界附近的载荷 | 不引入空载荷或边界兼容回归 |
| 字符与路径 | 中文、补充平面字符、空白密码、格式合法但某平台不能恢复的名称 | 密码字节语义保持；平台恢复限制不误报为格式损坏 |
| KDF 与资源 | 非默认合法参数，以及超过所设运行预算的文件 | 合法且预算允许时可读；超预算在执行昂贵工作前拒绝 |
| 换密 | 两算法及文件/目录、压缩与未压缩；另存和显式替换 | 输出仍是版本 1，新密码有效，旧密码打不开新文件 |
| 无回退 | 未知版本、篡改版本、v1/v2 内容混合、合法前缀后的坏头部 | 只进入指定版本流程，失败不尝试其他版本 |

换密的固定历史输入用于读取兼容；随机盐和 nonce 使新输出无需与某份密文逐字节一致。检查源格式、参数保留语义、随机字段更新及实际恢复内容。保留源文件和历史副本继续能用旧密码打开，也属于验收结果。

## 3. v2 编码与密码向量

### 向量形态

先建立可人工检查的最小编码与密码学向量，再建立完整文件向量。每个向量说明输入字节、规范版本、确定性测试随机材料、派生中间值、序列化字节、认证上下文、预期密文或预期错误阶段。

固定随机源只进入测试注入接口，不能成为生产 CLI 选项。中间密钥只来自公开测试输入。至少使用一种与生产编解码路径独立的方式复核向量，避免把同一个实现生成的输出直接写成唯一正确答案。独立复核不代表已经完成外部安全审计。

候选目录为 `tests/fixtures/v2/`。在布局与套件参数确定前，此处不填入猜测的十六进制“标准答案”。

### 必备向量清单

| 分类 | 正向向量 | 必须拒绝的变异 |
| --- | --- | --- |
| 识别与版本 | 最小合法前缀、版本分发 | 短前缀、错误魔数、未知版本、失败后跨版本回退 |
| 公共头与包装 | 两套数据算法及匹配包装算法的完整解锁链、32 字节头 HMAC 与 16 字节 AEAD 标签 | 长度溢出、非法编号、非法参数、包装或头字段替换、未知类型或标志、非零保留字段、截短标签 |
| 密钥派生 | 32 字节 DEK、Argon2id 输出到包装密钥及各用途的 HKDF-SHA256 精确派生值 | 错用途、错容器身份、错版本、错套件导致认证失败 |
| 密码 | UTF-8、前后空白、不同 Unicode 编码形式 | 错误密码不释放已解锁状态，不将不同字节静默归一化 |
| 记录 | 空载荷、单块、多块、每个记录类型、块边界 | Tag 或密文修改、序号重复与回退、记录错序、跨容器拼接、类型替换 |
| nonce 与用量 | 各用途的首值、边界值和最终允许值 | 计数器回绕、域碰撞、超过套件单条或累计使用上限 |
| 结束 | 空容器与非空容器的有效结束记录、精确 EOF | 缺少结束、伪造结束、错误计数或长度、重复结束、额外尾部 |
| 目录清单 | 单文件、空目录、多层树、空文件、多块文件；父条目在前，完整清单分片与计数 | 重复条目、失效父引用或非根条目的父 ID 不小于当前 ID、非法路径组件、清单分片缺失/重复/错序、完成声明不符、未声明数据 |
| 小文件合包 | 单文件包、多文件包、达到目标及越过目标、尾包、大文件前后衔接 | 认证有效但映射重复/遗漏/重叠/越界、偏移溢出、文件顺序错误、未声明尾部、超过记录或映射硬限制 |
| 独立帧与回退 | 开关压缩、整包与大文件块、可压缩与不可压缩内容、未压缩及单帧混合记录 | 认证有效但帧损坏、外部字典、拼接或可跳过帧、帧尾多余数据、输出长度不符、压缩关闭却出现压缩记录 |

向量中的“拒绝”必须对应最终规范确立的规则。布局不采用的字段不虚构测试。首版采用明确拒绝未知语义的固定编码及单完整帧约束；具体字段编号、认证字节和错误阶段需在实现前补齐。

### 合包边界

以暂定目标 `B = 4,194,304` 字节建立精确整数样本，避免用小数 MB 作为唯一测试输入。以下检查写入分包结果，再通过解密、验证和换密核对文件内容；资源与性能测量仍按后续计划执行。

| 输入或情形 | 预期 |
| --- | --- |
| `B - 20,480` 字节后加入 20,480 字节小文件 | 同一包恰好达到目标并封包 |
| `B - 10,240` 字节后加入 20,480 字节小文件 | 同一包超过目标 10,240 字节，第二个文件不拆分，随后封包 |
| 两个各 `B - 1` 字节的文件 | 同一包内容为 `2B - 2`，允许越过目标，仍受独立硬限制 |
| 单个大小恰好为 `B` 的文件 | 进入大文件分块路径，不补进已有小文件包 |
| 小文件、大文件、小文件 | 先封闭前包，大文件独立处理，尾块不与后续小文件合包 |
| 末尾不足目标、因硬限制提前封包 | 文件完整恢复；读取器不因包未满软目标拒绝 |
| 全空文件/目录，或空条目穿插小文件 | 空条目只在清单中出现，不产生零字节数据片段或空数据包 |
| 大量 1 字节文件 | 加入前检查映射条目数与编码硬限制，必要时提前封包；单条无法容纳时明确失败 |
| 源文件在处理期间增长或缩短 | 不突破大小预算，不按旧映射截断或补齐内容，不发布最终输出 |

压缩开启时检查整包选择一种数据编码；完整压缩帧长度等于或大于原始数据长度时回退未压缩编码。映射信息保持加密且不压缩，包内偏移针对解压后的数据区。对认证有效的恶意映射检查起点、连续覆盖、顺序、重复、整数溢出和清单长度不符。

## 4. 读取状态机与信任边界

对每种读取操作记录已到达的阶段，使用观察点或受控依赖注入验证先后关系：

```text
有界公共解析 → 运行预算检查 → 解锁与头认证
    → 记录认证 → 允许的解压或清单处理
    → 结束记录与全局校验 → 精确 EOF → 提交最终输出
```

- 在块认证成功前，不把该块明文交给 Zstandard、清单解析器、终端或最终输出。
- 块认证成功仍不代表整个文件有效；晚到的认证错误、缺少结束和尾部追加必须阻止提交。
- 正常 EOF、缺失记录、IO 失败与认证失败分别处理，不能折叠成“已读取完成”。
- 在每个固定字段、可变字段、Tag、帧与结束记录附近截断，覆盖一次读取返回短数据和不同输入分段方式。
- 测量声明长度与实际剩余数据不符时的行为，确认不会按不可信长度无界分配或递归。
- 文件数据的记录数量、编码字节数、逻辑字节数以及清单映射均独立核对；空文件也需要明确完整性证据。
- 合包整体认证完成后才解析映射、按需解压并向各文件分发；4 MiB 软目标、映射开销和记录硬限制分别核算。

对已经通过 AEAD 认证的测试输入，再检查恶意清单和压缩内容；只有随机翻转密文的测试通常到认证阶段就停止，覆盖不到后面的解析器。

## 5. 命令与事务验收

| 操作 | 必须验证的行为 |
| --- | --- |
| 新建格式选择 | 显式创建 v1/v2；开发期默认 v1，稳定发布切换默认前检查帮助与实际行为一致；选择 v1 时拒绝 v2 专有选项 |
| 未解锁 `info` | 不要求密码；只显示允许公开的字段；不把字段解析成功表述为认证成功 |
| `list` / `-l` | 两种写法的参数、密码输入、输出及错误行为完全一致；清单全部认证并检查结构后显示；结果明确尚未完成全文件验证 |
| `verify` | 覆盖全部数据、独立帧、清单映射、结束和 EOF；不生成恢复文件，也不暂存完整解密载荷 |
| 解密恢复 | 要求显式输出；v2 按指定路径恢复，不自动改用归档名称或追加后缀；v1 保持原扩展名规则；最终提交前完成全部验证，冲突或非法路径不覆盖已有内容 |
| `rekey` / `-r` | 别名等价、密码三次交互、另存与替换条件一致；保持源版本，使用新数据密钥并完整重加密 |
| 压缩开关 | 默认关闭，沿用 `compress` / `-z` 与 `no-compress`，压缩等级暂保持 3；v2 执行独立帧及无收益时的未压缩回退规则 |
| 进度 | 终端向 stderr 显示，重定向时不刷新动态行，允许关闭；阶段与字节口径正确，未知总量和 KDF 不伪造百分比；不泄露密码、明文或密钥 |
| 安全取消 | 在支持的检查点停止，提交前清理临时输出并保留原文件；成功提交后不报告回滚 |

内容列表需要两组有意不同的文件：一组清单有效但后续数据损坏，另一组清单自身损坏。前者允许只完成清单检查但不得声称全文件验证，后者必须失败。清单文本包含控制字符时，终端输出不能执行这些控制序列。

换密逐项比较原始内容、算法及约定保留的参数，检查新旧密钥材料独立；错误密码、源内容不合法、超预算或新输出校验失败均不能提交。保留原文件时它继续可用；显式替换时其他硬链接仍指向旧数据，不能宣传旧密文已被销毁。

取消注入覆盖密码输入、KDF 前后、头认证、块处理、清单校验、最终校验和提交前后。KDF 无法即时中断时，验证取消请求被记住并在安全边界处理；不能用永远停在 KDF 内的模拟接口宣称生产库支持即时取消。

复用并扩展平台事务的故障注入，覆盖写入失败、临时磁盘耗尽、刷新失败、源文件变化、目标冲突、重命名失败和提交后目录持久化失败。每项记录文件是否已替换；提交之后的失败提示不得承诺原文件还在。

强制终止或系统崩溃与可处理取消分开测试。前者可能留下临时文件；应在明确的文件系统持久化假设下检查最终输出，记录替换前后可能观察到的状态、恢复与残留处理策略，不承诺所有硬件故障下都可回滚。正常异常清理结果不能作为崩溃安全证明。

## 6. 资源与性能测量

本节保留后续验收计划。容量目标、KDF 成本与资源参数评估当前暂缓，不在本轮启动测量或调整已有默认值；有界解析、整数检查和密码套件使用限制仍是实现要求。

在冻结默认值前测量候选块大小和压缩参数。数据集应包括空输入、小文件、大文件、大量小文件、深目录、Unicode 名称、高可压缩内容、已压缩内容和随机数据。使用现有目录素材辅助回归，另外建立尺寸和生成方法可重现的合成数据。

| 测量项 | 记录内容 | 影响的决策 |
| --- | --- | --- |
| KDF | 设备、参数、耗时分布、峰值内存、并行度 | 新建文件默认值及读取时允许的预算 |
| 块大小与标签开销 | 吞吐、CPU、峰值内存、记录开销、小文件固定成本 | 默认块大小、块数量及缓冲上限 |
| 小文件合包 | 4 MiB 目标附近的实际包大小、映射开销、极小文件数量、压缩收益与峰值缓冲 | 合包目标、文件分类、映射及记录硬限制 |
| 独立压缩帧 | 相同输入下的压缩率、耗时、帧内存与输出上限 | 压缩参数与可接受的体积损失 |
| 完整清单 | 条目数、名称字节、树深度、解析内存及时间 | 清单编码、字节数、条目数和深度预算 |
| 验证和恢复 | 读取量、解压逻辑字节、临时磁盘峰值 | 流水线成本、磁盘需求和进度口径 |
| 完整换密 | 读写量、峰值内存、新密文临时空间与总耗时 | 用户预期及资源诊断，不把包装层视为 O(1) 换密 |
| 限额失败 | 在限制附近及超限时的内存、时间和磁盘占用 | 确认先检查后分配、早失败及累计计数有效 |

使用相同内容和设备比较 v1 与 v2，并区分 KDF 时间、压缩时间、数据认证时间和 IO。QEMU 基线用于兼容与故障回归，其耗时不能直接作为真实设备默认参数的依据。

对认证有效的解压炸弹、海量空条目、深树和超大声明长度，分别验证协议上限与可调运行限制。每个计数增加、长度乘加和尺寸转换都覆盖溢出边界；不能依靠实际申请巨量内存来触发测试失败。

块大小、总记录数、每密钥累计用量、KDF 参数、清单和总解压量的最终数值需附测量或密码套件依据。本文不预设安全常数，也不以“分块”作为无限文件大小的承诺。
